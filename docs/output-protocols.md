# 三路输出协议说明

本文档记录当前固件的三个输出通道：串口1、串口3、OLED。串口1用于开发调试，串口3用于树莓派二进制通信，OLED用于本地低频摘要。未实现或没有可靠数据来源的字段不写入协议。

## 总体分工

| 输出通道 | 面向对象 | 主要用途 | 代码入口 |
| --- | --- | --- | --- |
| 串口1 USART1 | 开发者 | 调试命令、调试日志 | `host_link.c` / `debug_uart.c` |
| 串口3 USART3 | 树莓派上位机 | 二进制短帧状态数据、上位机控制 | `raspi_link.c` / `system_status.c` |
| OLED | 本地观察 | 低频状态摘要 | `oled.c` / `system_status.c` |

## 串口1：调试控制台

### 串口参数

| 参数 | 值 |
| --- | --- |
| 串口 | USART1 |
| 引脚 | PA9 TX，PA10 RX |
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 数据格式 | 文本 |

### 命令

串口1命令只控制“是否打印到串口1”，不关闭模块本身。

| 命令 | 作用 |
| --- | --- |
| `ping` | 测试串口1收发，返回 `[CMD] pong` |
| `help` | 显示命令帮助 |
| `?` | 同 `help` |
| `status` | 查看当前调试打印开关 |
| `imu on` / `imu off` | 打开 / 关闭 IMU 调试打印 |
| `pad on` / `pad off` | 打开 / 关闭手柄数据调试打印 |
| `servo on` / `servo off` | 打开 / 关闭舵机输出调试打印 |
| `motor on` / `motor off` | 打开 / 关闭电机输出调试打印 |
| `enc on` / `enc off` | 打开 / 关闭编码器调试打印 |
| `ultra on` / `ultra off` | 打开 / 关闭超声波调试打印 |
| `odom on` / `odom off` | 打开 / 关闭里程计融合调试打印 |
| `odom reset` | 清零里程计累计距离、航向角和陀螺仪零偏校准状态 |

## 串口3：树莓派通信协议

本节描述串口3面向树莓派的二进制协议。协议目标是减少数据量、保证实时性、支持丢帧检测，并为后续时间同步预留时间戳字段。串口3不混入调试文本，调试文本统一走串口1。

### 串口参数

| 参数 | 值 |
| --- | --- |
| 串口 | USART3 |
| 引脚 | PD8 TX，PD9 RX |
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | 无 |
| 数据格式 | 二进制短帧 |

### 帧格式

一帧由帧同步、帧头、负载和校验组成：

```text
AA 55 | VER | MSG | SEQ | LEN | PAYLOAD... | CRC16
```

| 区域 | 字段 | 长度 | 类型 | 说明 |
| --- | --- | ---: | --- | --- |
| 帧同步 | `AA 55` | 2 | 固定值 | 帧头同步字节，用于从字节流中重新找到一帧开始 |
| 帧头 | `VER` | 1 | `u8` | 协议版本，当前固定为 `0x02` |
| 帧头 | `MSG` | 1 | `u8` | 消息类型 |
| 帧头 | `SEQ` | 1 | `u8` | 帧序号，0-255循环，用于丢帧检测、ACK匹配和调试通信质量 |
| 帧头 | `LEN` | 1 | `u8` | `PAYLOAD` 长度，范围 `0-64` |
| 帧体 | `PAYLOAD` | 0-64 | bytes | 具体消息数据，字段由 `MSG` 决定 |
| 校验 | `CRC16` | 2 | `u16` | CRC16-CCITT-FALSE，小端，覆盖 `VER` 到 `PAYLOAD`，不包含 `AA 55` |

### 基本约定

| 项目 | 约定 |
| --- | --- |
| 字节序 | 多字节整数统一小端 |
| 有符号数 | 使用二进制补码 |
| `SEQ` 用途 | 通信层序号，只用于丢帧检测、ACK匹配和调试，不承担时间戳职责 |
| 时间戳用途 | 需要实时性的消息在 `PAYLOAD` 内携带 `time_ms:u32` |
| 时间戳来源 | MCU上行使用 `mcu_time_ms`，树莓派下行使用 `host_time_ms` |
| 时间戳单位 | 毫秒 |
| 最大负载 | 64字节 |
| CRC算法 | CRC16-CCITT-FALSE，多项式 `0x1021`，初值 `0xFFFF`，无输入/输出反转，结果不异或 |
| 超时保护 | MCU超过 300ms 未收到有效树莓派控制帧时，应停止使用 HOST 控制源 |
| 调试输出 | 串口3不输出调试文本，调试文本统一使用串口1 |

### 时间戳与时间同步

| 项目 | 说明 |
| --- | --- |
| `SEQ` 是否用于时间同步 | 不用于时间同步，只用于通信层序号 |
| 为什么 `SEQ` 只有 0-255 | 它是循环序号，足够用于短时间丢帧检测和ACK匹配 |
| 时间同步字段 | 使用 payload 内的 `host_time_ms` / `mcu_time_ms` |
| 初始同步方式 | 树莓派周期发送 `0x03` 心跳，MCU可记录收到时的 `mcu_time_ms` |
| 后续扩展 | 如果需要更精确同步，可新增时间同步消息，不改变基础帧头 |

| 消息 | 周期 | 单帧长度估算 | 数据量估算 |
| --- | ---: | ---: | ---: |
| `0x81` 底盘状态 | 20Hz | 20字节 | 约 400B/s |
| `0x82` 编码器增量 | 50Hz | 20字节 | 约 1000B/s |
| `0x83` IMU原始数据 | 50Hz | 24字节 | 约 1200B/s |
| `0x86` 2.5D里程计融合 | 50Hz | 48字节 | 约 2400B/s |
| `0x84` 设备状态 | 1Hz | 16字节 | 可忽略 |
| 合计 | - | - | 约 5.4KB/s |

115200 8N1 的实际可用吞吐约 10KB/s 左右，上述配置有余量。

## OLED：本地状态摘要

OLED不作为完整通信协议，只显示低频摘要。当前每 1000ms 刷新一次。

### 显示内容

| 行 | 内容 | 示例 |
| --- | --- | --- |
| 1 | 当前控制源 | `SRC:PAD` |
| 2 | 前进和转向命令 | `F:200 T:-50` |
| 3 | 手柄连接状态 | `PAD:OK` 或 `PAD:NO` |
| 4 | 超声距离 | `UL:320mm` 或 `UL:--` |

### 控制源取值

| 显示值 | 含义 |
| --- | --- |
| `NONE` | 当前没有有效控制源 |
| `HOST` | 上位机控制 |
| `PAD` | USB手柄控制 |
| `SAFE` | 安全保护接管 |

## 当前不确定或未实现的内容

以下内容当前没有可靠数据来源或尚未实现，因此没有写入协议字段：

- 电池电压
- 电流
- 里程
- 真实车速
- 舵机角度的物理单位
- 更高精度的时间同步算法
- 有效轮距尚未实测，`wheel_track_mm=0` 时系统只使用 IMU 航向；测量并标定后才启用编码器差速航向融合
